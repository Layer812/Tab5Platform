# ArcadeTab5 — 限定基板MAME移植計画 R0

**状態:** 移植開始前の実装計画。X68KTab5の正式版は変更しない。

## 決定事項

- 独立した `ArcadeTab5` とする。X68KTab5をMAME組込みファームにはしない。
- 先に `tab5_platform` を抽出し、APIを固める。その後にエミュレータを接続。
- ゲスト環境は転用せず、Tab5のLCD／音声／SD／USBと最適化だけを再利用。
- MAME 0.37b5を**初期の技術候補**とする。採用確定前に旧MAME非商用ライセンスと個別ファイルを確認。
- 最初は8bitの1基板、後で必要なCPU/音源を追加。MAME全体は組み込まない。
- 利用者が合法的に準備したROMだけをSDから読み込む。ROM/BIOSはファームウェアに同梱しない。

## 最初に完成させるユーザー機能

1. Tab5で大きな文字のArcadeTab5ランチャーを表示。
2. `/sdcard/arcade/roms/`のROM候補一覧を表示（ZIP形式対応はMAME側のROMローダで判断）。
3. USB Joypad／Keyboard、画面タッチで操作できる。
4. 8bit基板1種類をロードし、実画面・音声・入力が一致する。
5. メニューへ戻り、別ROMの選択・エラー表示ができる。

## 最小実装順序

| 段階 | 実装成果物 | 完了条件 |
|---|---|---|
| P0 | `TAB5_PLATFORM_SPEC_R0.md`、API header | R6との差異と共通化範囲が明記される |
| P1 | `tab5_platform` コンポーネント | PX68KをリンクせずIDF 5.5.4でビルド可能 |
| P2 | ArcadeTab5ネイティブランチャー | 実機LCD/タッチ/USB/SD/音声が一つのアプリで利用可能 |
| P3 | 8bit基板ドライバ＋MAMEの最小核 | ROMから起動し描画／音声／入力が動作 |
| P4 | 実機性能改善 | 動作フレーム時間、音声欠落、メモリ消費を確認し改善 |
| P5 | 公開用セット | 権利確認、ソース、ROM無しBIN、ライセンス文書、使用方法 |

## 技術上の注意

- X68KTab5の `tab5_video.cpp` と `tab5_audio.cpp` はPX68Kのイベント・画面状態を参照しており**そのまま別アプリへコピーしても使えない**。ホスト処理とゲスト処理を境界で切り離す。
- X68KTab5の `src/CMakeLists.txt` は `REQUIRES px68k` のため新規作成。
- X68KTab5ルートの`platformio.ini`は旧Cardputer設定なので利用しない。`idf.py`（Native ESP-IDF）を正とする。
- 人手による旧ROMの配布を避ける。データの利用権限はゲームごとに確認する。
- 旧MAMEライセンスの非商用制限はM5Burner経由で無償配布する場合も残る。ライセンスレビュー前に「リリース可能」と確約しない。
- R6が対応するST7121/ST7123/ILI9881Cの画面互換、ES8388 256fs、Speaker通知、LCD DoubleFBを退行させない。
- 実機に書く場合はアプリ領域限定の非破壊手順を優先し、既存のHumanXDF/ブートローダ/パーティションテーブルに触れない。

## 最初に選ぶ基板の理由

**Pac-Man系のZ80基板**を暫定第一候補とする。CPU、入力、タイル／スプライト、割込み、サウンドなど、基礎的なアーケードの全系統を比較的小さく検証できる。縦画面変換と画面上下の余白の設計にも使える。ゲームROMは同梱しない。最初の基板は法的に用意できるROMと実装量を比較して最終確定する。

## 後続候補

CPS-1やSega System 16等の68000系は、第1基板の完成後に独立して性能・基板仕様を評価する。X68KTab5のMusashiは再利用候補だが、MAMEのCPUメモリ・割込み契約に合わせたadapterが必要であり、そのまま直結しない。
